# 模拟校园卡真机验收

本文是待执行的验收步骤，不是已通过测试的声明。只使用自己的空白 MIFARE Classic 1K / 4K 测试卡和虚拟金额；至少准备 A、B 两张卡。记录固件版本、手机型号、微信版本、卡型及失败现象。首版无退款，验收充值不涉及真实钱款。

## 准备

- 构建 `esp32-s3-n16r8` 成功，人工确认串口后烧录；保留串口日志。
- 按 README 接线，OLED 为 SSD1306 128×64，RC522 使用 SPI，均为 3.3V。
- 用自己的 AppID 生成 `.local/wechat/`，导入并真机预览，完成后台隐私配置及手机授权。
- 确认小程序连接的是 `S3-CAMPUS-XXXX`，显示 OLED 与读卡器均就绪。
- 测试卡 A、B 相关数据块可覆盖，默认 Key A 为全 FF；不使用真实校园卡或其他重要卡片。
- 本次计划用 S50 空包卡作为 A、S50 异形卡作为 B；先确认两张实际识别为 MIFARE Classic 1K（兼容芯片同样需通过实际读写确认），分别记录卡号与测试结果。外形不影响业务，但需要分别验证贴卡位置和写入稳定性；本项尚未实测。
- 每个用例记下业务 id、开始余额、预期变化和实际结果。未确认交易未恢复前不清空 NVS、不更换设备。
- PC 双端验收使用 Windows Chrome / Edge，先关闭占用串口的监视器；PC 走 USB、手机走 BLE，以同一台终端为对象。演示设备模式另记，不得混作真机通过。

## 基础闭环

| 用例 | 操作 | 预期 |
| --- | --- | --- |
| 开卡 A | 输入“测试甲”和“20260001”，启动开卡，30 秒内刷 A | 成功后卡片信息匹配、余额 0；流水与 OLED / 小程序一致 |
| 开卡 B | 输入另一组身份，刷 B | A、B 独立，不串卡 |
| 充值 | A 充值 50.00 | 余额从 0 到 50.00，仅一笔成功结果 |
| 消费 | A 在“食堂”消费 12.50 | 余额变为 37.50，金额、场景和卡片一致 |
| 待机读卡 | 没有等待任务时刷 A | 仅显示资料和 37.50，不生成新的充值 / 消费 |
| 卡片隔离 | 待机刷 B，再刷 A | B 余额仍为 0，A 仍为 37.50 |
| 余额不足 | A 消费 40.00 | 明确拒绝，余额保持 37.50，无成功扣款 |
| 金额边界 | 输入空、0、负数、多于两位小数和超上限金额 | 页面或固件拒绝，不改变卡片；0.01 可按规则正常交易 |
| 文字边界 | 姓名和场景测试中英文及超过 UTF-8 字节限制的文本 | 合法内容一致显示；超限明确拒绝，无半个汉字或半笔任务 |
| 等待过期 | 启动充值后等 30 秒以上再刷卡 | 原任务过期，不发生充值；新操作需重新启动 |
| 取消等待 | 启动任务后尚未刷卡即取消 | 任务取消，随后刷卡只查询 |

卡片持久化核对：完成充值和消费后重启设备，刷 A，仍读到已确认的身份、余额和序号；小程序重连后读取设备状态及设置。

## 重复刷卡、重复请求和断线

| 用例 | 操作 | 预期 |
| --- | --- | --- |
| 一直贴卡 | 完成一笔消费后让 A 持续贴在读卡器上至少 10 秒 | 不反复消费，不重复生成成功流水 |
| 移开再放回 | 完成交易后移开再刷 A，不启动新任务 | 只查询原余额，不自动再扣款 |
| 相同业务 id | 用调试客户端按协议重复发送完全相同的 arm 请求，包括完成后的重试 | 返回原任务或原结果；总额只变动一次，流水不重复 |
| 查询原结果 | 用 result 查询该 id；再查询不存在的 id | 已知 id 的结果一致；未知 id 返回 result:null，不能视为成功 |
| 写入前断线 | 等待刷卡期间关闭手机蓝牙 | 小程序不宣称成功；重连后查 state / 原 id，以设备状态为准 |
| 成功时断线 | 交易进行或刚成功时断开手机，再重连 | 原业务 id 能确认结果；不自动用新 id 再加款 / 扣款 |
| 回应超时 | 阻断或延迟客户端接收完整通知 | 页面不以 BLE write success 当交易成功；超时后保留原 id 查询 |

`arm` 的业务 id 是 16 位十六进制字符串；BLE 分包 messageId 与业务 id 不是同一字段。重复请求用同一个业务 id，且内容保持一致；不要通过点击创建新交易来模拟重试。

## 移卡与恢复

1. 记录 A 当前余额和序号，启动一笔小额充值或消费。
2. 在读写期间移开 A，尝试捕捉“结果未确认”状态。读写窗口很短，未触发此状态不能算此项通过；不要拉扯接线或短接电源制造故障。
3. 若交易已经明确成功，余额只能变动一次；若明确未开始则保持原余额；若为 uncertain，OLED / 小程序应提示刷回原卡，且禁止启动另一笔交易或取消该交易。
4. uncertain 时刷 B，不能把 A 的待恢复金额应用到 B；仍要求 A。
5. 刷回 A，完成恢复。以原业务 id 查询最终结果，核对卡片、设备流水与新余额一致，序号不出现重复扣款对应的额外递增。
6. 再次移开并刷 A，结果稳定。完成该笔交易后才能进行下一用例。

## 断电恢复

先完成一笔正常交易，验证重启后余额可读。随后使用少量虚拟金额，分别尝试在等待刷卡、写入中、卡片已写但客户端未确认时断开开发板电源；每次测试独立完成并记录。

恢复供电后检查：

- 没有开始写卡的任务不应凭空产生充值或消费。
- 已持久化待确认记录但未确认完成的交易应保留恢复提示；重新刷原卡后再确定最终结果。
- 已写入有效新快照的交易恢复时只确认原结果，不再额外加款或扣款；旧快照仍有效且新快照不完整时，依协议恢复同一笔交易。
- B 卡不能代替 A 完成恢复；不接受新任务覆盖待恢复任务。
- 恢复后小程序按原业务 id 查询，余额只变动一次，流水只有一个最终结果；再次重启后仍一致。

单纯“在交易附近拔过电”无法证明覆盖了 journal 已保存、写卡中和回读后等阶段。应结合串口日志确认命中阶段；未命中的阶段标记“未覆盖”，不能标记通过。不要在恢复测试期间使用擦除 Flash / NVS 的上传方式，否则原设备的恢复依据也会被清除。

## OLED 与小程序展示

- 分别设置金额数字的 12、16、24、32 字号，刷卡核对金额和固定 12 像素的中文标签可读，无旧画面残留；所有效果下，超宽金额都降为 16 像素完整显示。长中文在 slide 中滚动，其他模式允许截断，不能据此推断所有文字都已显示。
- 分别测试 static、slide、type，确认数字静态显示、上滑 / 长内容滚动、金额逐字出现；充值、消费、余额不足和未确认状态有可区分的提示，动画不应阻止交易状态确认。
- 设置 holdMs 为 1500 和 10000，确认播放时长变化；设备重启、小程序重连后读回同一设置。
- 带动画时持续刷卡、断开 BLE，屏幕与卡片业务保持响应，不因动画重复执行交易。
- 静态模式下待机和等待装饰停止；逐字、上滑完成后，内容不变时不再发送相同全屏。主机计数测试检查发送次数，真机检查画面不闪烁、金额不在 650 毫秒处倒退或重播。
- 未校时记录显示“设备未校时”或明确标注收到时间；已校时的记录时间合理，不把收到时间冒充交易时间。
- logs 最多保存 20 笔，每页最多 5 条，完整读取同一 revision 后再显示整份列表；不要把这 20 笔当作完整长期账本。

## PC、USB 与双端并用

| 用例 | 操作 | 预期 |
| --- | --- | --- |
| USB 连接 | 从 PC 控制台选择开发板串口，保持 115200 波特率 | 获取真实设备状态；忽略非 JSON 启动日志，不把日志误作失败回应 |
| USB 接口 | 使用数据线连接 ESP32-S3 原生 USB / USB-CDC，核对双口板接口标签 | 选择暴露本固件 Serial 的端口；仅有 USB 转串口但未连到该接口时不能误判为已建立业务连接 |
| 串口占用 | 保持其他串口监视器占用，再尝试连接 | 明确报告连接失败；关闭监视器后可重新选择连接，不产生交易 |
| PC BLE | 断开占用设备的其他 BLE 客户端，通过浏览器选择 S3-CAMPUS 设备 | 订阅成功后读取状态；不以串口连接状态代替 BLE 状态 |
| 双端争用 | PC 启动充值等待任务，手机尝试创建新消费 | 只保留第一笔任务，另一端显示忙碌或已有待办；卡片不被两笔同时扣写 |
| 双端结果 | PC 与手机分别观察同一笔交易 | 余额、业务 id 和终态一致；一端断线不触发另一笔补单 |
| 取消一致 | PC 启动等待任务、手机取消，再刷卡 | 两端更新为取消；刷卡只查询，不充值 |
| 结果未确认 | 一端触发 uncertain，另一端查询、尝试取消或新建任务 | 原任务仍存在，不能取消或覆盖；刷原卡恢复后两端一致 |
| 模式隔离 | PC 切换真实设备与“演示设备” | 明确显示当前模式；演示充值不影响实体卡，真实记录不被假设备结果覆盖 |
| 商品配置 | 编辑商品名、场景、价格和充值档位，再选择交易 | 发起的业务参数与选择项一致，旧订单待核对时不会用新配置替换原参数 |

## 流水分页、筛选与导出

1. 准备至少 7 笔终态记录，确认控制端连续请求 offset 0、5，使用同一 revision；返回顺序正确、无重复或漏项。
2. 页间制造一笔新交易。当前快照应保持完整一致，刷新下一轮后才出现新记录；不能把两轮记录混在一起。
3. PC 经 USB、手机经 BLE 同时分页。各自快照不应互相失效；同一传输通道快照过期时只整轮重拉一次。
4. 第二页读取中断开连接，页面不把第一页显示为完整新账本；重连后完整刷新，不沿用失效 revision 接着拼接。
5. 测试空流水、刚好 5 条、超过 20 条的情况；最多返回最近 20 条，过滤结果与统计金额只基于当前加载记录。
6. CSV 导出核对业务编号、场景、金额、状态、余额和时间说明；中文正常，未校时不伪造日期。导出条数与当前选择的记录范围一致。

## 电池模式与屏幕电源

- 分别设置亮度 1、80、255，确认屏幕亮度变化；重复应用同一值不会反复发亮度命令。重启并重连后设置可读回。
- 设置闲置 10 秒，停止业务操作后 OLED 熄屏；持续刷新状态或读取流水不应维持常亮。设置 0 后不自动熄屏。
- 熄屏期间手机连接仍在、原卡数据保留；显式唤醒、新卡、业务或设置操作使首帧完整恢复。不要把 OLED 熄屏误认为整机断电。
- 有等待或待核对交易时，按设备策略保持屏幕可见，熄屏不能取消任务、清除 journal 或改变余额。
- 电池模式下待机和等待的循环装饰停止；交易成功 / 失败动画仍能播放，静态模式继续保持静态。比较刷卡感知速度：闲置时允许省电检测延迟，等待交易时仍及时响应。
- 页面报告电池采样未配置、电压 `null`，不显示随意生成的百分比或剩余时长。供电模式开关不能伪装成真实电量检测。
- 记录所用电池、充电 / 稳压模块与供电接法；本项目没有提供 ADC 电压标定或续航实测结论。
- 读取连接诊断，核对 uptimeMs、可用 / 最低堆内存、循环与读卡耗时、BLE / USB 状态和队列长度随实际操作变化；记录短帧轮询在 S50 空包卡、异形卡上的检出情况。诊断数字不替代读写、射频或电池续航实测。
